A.1  VOICE-TO-EXPENSE  (Modals.jsx → AddSheet)
================================================================================

PURPOSE
  Skip the typing — speak an expense and an LLM parses it into the form.
  Example: user says "spent twenty shekels on coffee" → form auto-fills
  amount=20, category=Food, description=coffee.

WHERE
  Visible inside the AddSheet bottom-sheet (the + Add Transaction modal).
  A pulsing mic button next to the form fields.

HOW IT WORKS
  - Native Web Speech API (window.SpeechRecognition / webkitSpeechRecognition)
  - Locale set per language: ar-SA for Arabic, en-US for English
  - Transcript fed to parseTranscriptWithLLM(transcript, lang) — calls the
    OpenAI-compatible Chat Completions endpoint with a strict-JSON schema:
        { amount, category, description }
  - applyParsed() writes the values into the AddSheet state, sets
    voiceState='success', shows a "Pre-filled from voice" toast

VOICE STATE MACHINE
  idle → listening → processing → success | error

HIDDEN DEMO ESCAPE HATCH
  Double-clicking the mic skips both the microphone AND the LLM call
  and pushes a canned bilingual sample through applyParsed (forceMock).
  Lets you demo voice-to-expense reliably even on hostile Wi-Fi.

i18n COPY
  addSheet.{voiceStart, voiceListening, voiceProcessing, voiceFilled,
            voiceFilledDemo, voiceUnsupported, voiceErrorMic,
            voiceErrorParse}  — EN + AR

ENV VARS
  VITE_LLM_API_URL  (defaults to OpenAI Chat Completions)
  VITE_LLM_API_KEY
  VITE_LLM_MODEL    (defaults to gpt-4o-mini)

A.2  AI MONEY COACH  (aiCoach.js + components/AICoach.jsx)
================================================================================

NEW FILES
  src/aiCoach.js           (347 lines) — LLM + ElevenLabs TTS module
  src/components/AICoach.jsx (425 lines) — coach card UI

WHERE
  Reports tab (the "AI Coach" card sits at the top of Reports).

PHASE 1 — WEEKLY/DAILY SUMMARY
  generateCoachSummary({ role, transactions, lang })
    System prompt asks for strict JSON:
      { headline, body, tips:[{icon,text}], spoken }
  Headline + body + 1-4 tips render as a readable card.
  "Generate weekly recap" / "New recap" button cycles fresh summaries.

PHASE 2 — CONVERSATIONAL CHAT
  chatWithCoach({ role, transactions, lang, history, userText })
    Returns { reply, spoken }. Maintains last 6 turns of conversation
    history so follow-ups have context.
  Chat input has:
    - Text field
    - Mic button (Web Speech API for the question, then routes through
      sendChat() — same locale rules as Voice-to-Expense)
    - Send button
  Replies render as bubbles in a scrollable log (auto-scrolls on new msg).

ELEVENLABS TTS
  speak(text, lang) → POST audio/mpeg from
    https://api.elevenlabs.io/v1/text-to-speech/{voiceId}
  Model: eleven_multilingual_v2 (handles EN + AR with one voice).
  Per-language voice override available
    (VITE_ELEVENLABS_VOICE_ID_EN / _AR).
  speakSafe() → falls back to native window.speechSynthesis if the
    ElevenLabs key/network fails. cancelSpeaking() stops both paths
    cleanly.
  Coach reply is auto-spoken when received; play/pause button
    available on the summary card.

DEMO ESCAPE HATCHES (hidden)
  • Double-click "Generate" → forceMock=true → returns hand-tuned EN/AR
    summary from MOCK_SUMMARIES.general (no network).
  • Double-click "Play" → uses native speechSynthesis instead of
    ElevenLabs (no network).
  • Double-click the chat mic → skips speech recognition AND the LLM,
    pushes a canned bilingual chat exchange.

i18n COPY

         play, pause, resume, stop, speaking,

         askLabel, askPlaceholder, askMicHint, askListening,

A.3  SMART RECEIPT SCANNER + RECIPE GENERATION  (visionLLM.js)
================================================================================

NEW FILE
  src/visionLLM.js  (199 lines) — vision LLM extractor + recipe gen

PURPOSE
  Snap a photo of a grocery receipt → vision LLM extracts the total
  amount AND uses the ingredient list to generate 3 cheap, quick
  student recipes with cost + savings estimates.

WHERE
  Two entry points:
   (1) AddSheet → ScanLine "Scan receipt" button (file picker → upload)
   (2) Smart Receipt CTA on the University Student dashboard
       (uses autoScanReceipt prop → AddSheet auto-opens file picker)

API
  readReceiptImage(file, lang) → { amount, recipes }
    POST https://api.openai.com/v1/chat/completions
    model: gpt-4o-mini
    body: messages with one image_url block (data URL of the upload)
    response_format: { type: 'json_object' }

  readReceiptImageSafe() → wraps with mock fallback when key/network fails.

PROMPT (bilingual EN + AR)
  Asks for strict JSON:
    { amount: number,
      recipes: [
        { name, time, ingredients[], estimatedCost, savings }
      ] }
  Each recipe estimates how much the user saves vs ordering takeout.

NORMALIZATION
  normalizeReceipt(raw) → caps recipes at 3, coerces all numeric fields
  to Number(), filters invalid ingredients.

MOCK FALLBACK
  Hand-tuned bilingual mock aligned to the demo receipt
  (Tan Hung Asian Grocery, $22.73, 13 items) so the offline demo path
  matches what's printed on the screen.

UI INSIDE ADDSHEET
  - "Scan receipt" button with ScanLine icon (live/demo pill)
  - File <input type="file" accept="image/*"> hidden, triggered by click
  - On success: form auto-fills with amount + "Groceries" category +
    name "Scanned receipt"; recipes card appears below the form.
  - Recipes card: ChefHat icon, 3 recipe rows with name + time +
    ingredients chips + cost + savings, "Total savings" footer.
  - Hidden demo: double-clicking the scan button forces the mock path.

i18n COPY
  addSheet.{scanReceipt, scanHint, scanProcessing, scanFilled,
            scanFilledDemo, scanError, scanLive, scanDemo,
            recipesTitle, recipesSub, recipesFooter, recipeCost,
            recipeSaves, totalSavingsTitle, totalSavingsSub}

ENV VARS
  VITE_VISION_API_URL   (defaults to OpenAI Chat Completions)
  VITE_VISION_API_KEY   (inherits VITE_LLM_API_KEY when blank)
  VITE_VISION_MODEL     (defaults to gpt-4o-mini)

B.2.1  Transaction anomaly detectors    (src/transactionAnomalies.js)
──────────────────────────────────────────────────────────────────────
NEW FILE — pure JS, no LLM calls, runs over the transactions array.

DETECTORS
  • detectDuplicates(txs, { withinDays = 5 })
    Same merchant + same amount within 5 days. Tolerates ±1¢ noise.

  • detectSubscriptions(txs)
    Same merchant in >=2 distinct calendar months with stable amount
    (within ±10%). Catches forgotten Netflix/Spotify/gym memberships.

  • detectCategorySpikes(txs, { now })
    Recent week vs prior week sum per category. Flags growth >150%
    AND >$30 absolute. Brand-new categories surface as a quieter info.

  • detectAnomalies(txs)
    Convenience aggregator with per-kind caps so the inbox doesn't drown
    (1 duplicate, 2 subscriptions, 2 spikes max).

WIRED INTO
  notificationFeed.js — anomalies become first-class items in the bell
  inbox, with bilingual copy. Duplicates are pinned to the top.

DEMO DATA SEEDED
  • Family Parent: duplicate Carrefour ($142.50, 3 days apart),
                   Netflix $14.99 across 3 months
  • University   : duplicate Tan Hung ($22.73, 2 days apart),
                   Spotify Premium across 3 months
  • Employee     : Spotify across 3 months, Gym across 2 months

B.2.2  Gemini integration              (src/cheerLLM.js)
──────────────────────────────────────────────────────────────────────
NEW FILE — wraps Gemini's REST API to generate one warm sentence per
goal, per session.

WHY NOT STATIC TEMPLATES
  Arabic gender / plural agreement. Static templates can't handle
  iMac (مذكر), دراجة (مؤنث), and "Football boots" (جمع) all at once.

ENDPOINT
  https://generativelanguage.googleapis.com/v1beta/models/{MODEL}:generateContent

MODEL
  gemini-2.5-flash-lite (chosen for generous free-tier quota and speed)

PROMPT DESIGN
  - "max 14 words", "no numbers", "no markdown", "use one emoji",
    "return only the sentence"
  - Arabic prompt explicitly says: "راعِ القواعد العربية —
    جنس الكلمة (مذكر/مؤنث) وجمعها"

CACHING
  In-memory Map keyed by (lang|band|name|goal). Survives within page
  lifetime; cleared on reload (intentional — fresh phrasing each
  session keeps the demo lively).

FALLBACK
  cheerLLM throws on any failure (no key, network, throttle, parse).
  GoalCheerCard already shows a static gender-neutral string while
  loading; that string remains if the LLM call fails.

ENV VARS (in .env.local — gitignored)
  VITE_GEMINI_API_KEY  = <key>          (added)
  VITE_GEMINI_MODEL    = gemini-2.5-flash-lite
